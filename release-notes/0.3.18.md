# 0.3.18

This release makes automatic maintenance safer. Restarts, backups, and updates no longer run on top of each other. Manual updates work again after a Funcom release, and the dashboard shows more accurate and more useful information: real gateway health, per-server uptime, disk usage, and an optional auto-refresh.

## Reinstall step

After updating the desktop app, open each server's **Management Service** card and click **Update** so the refreshed host service is pushed. The fix that stops automated tasks from overlapping lives in the host service and only takes effect once it is updated. Everything else works as soon as the desktop app is updated, and servers whose host service is not updated yet keep working as before.

## Fixed

- **Automated restart, backup, and update no longer overlap (#37).** Until now the nightly restart, scheduled backups, and automatic updates could run at the same time. A restart in the middle of an update, or a backup while every map server was booting, could leave the server needing manual repair. They now run one at a time: a task that is due while another one is running waits for it to finish, and the task log says what it is waiting for. The nightly restart is also skipped when an automatic update was applied in the last 30 minutes, because the update already restarted every server, so players are not kicked a second time without a countdown.
- **Update Server no longer reports a failure after a successful update (#24).** Funcom's update script exits with an error at the very end of every update after the first one, even though the update worked. The app now treats the update as successful when the script reports that it finished and the live server is running the new version. A genuinely failed update is still reported as a failure.
- **You can now apply a fresh Funcom update from the app (#18).** The Update tab only offered Update Server once the new build was already downloaded on the host, so right after Funcom published an update it said "no update pending" and gave you no way to apply it. Update Server is now always available. It downloads the latest build from Steam and applies it, and it is still highlighted when a newer build is already downloaded.
- **The Users tab auto-refresh switch now stays off (#25).** Turning Auto-refresh off is remembered when you switch tabs or restart the app. Polling also pauses while the BattleGroup is stopped, so the app no longer freezes for a moment on every check while the game database is down.
- **Dashboard information now matches Funcom's tools more closely (#21).** The Gateway tile shows the gateway's own health (for example `Healthy`). The value it used to show, the state of the map servers, now has its own **Servers** tile. Each row in the server list shows how long that server has actually been running, not how long the BattleGroup has been up.
- The uninstall dialog for the management service no longer claims that its history database is deleted. Settings, run history, and the welcome-package ledger are kept, so reinstalling picks them up again.

## Added

- **Dashboard auto-refresh (#22).** The server status refreshes every 30 seconds while the app is open. It runs quietly in the background, pauses while a Start, Stop, Restart, or Update is running, and does not retry a server that cannot be reached. Turn it off with the **Auto-refresh** switch next to the Refresh button; the setting is remembered.
- **Disk usage on the dashboard (#38).** New tiles show how full the server's disks are, for the root filesystem and for the Kubernetes storage when it is on a separate disk. They turn amber at 80% used and red at 90%, so you can act before the server runs out of space.

## Notes

- No configuration changes are required. Existing schedules, welcome packages, and enable switches keep their current settings.
- With auto-refresh on, the app runs a few quick status commands on the server over SSH every 30 seconds while it is open.
- The manual Ubuntu setup guide was also updated (#36): its checks no longer close your SSH session, and it explains the new `setup/vm_ip.sh` script. Do not run `battlegroup change-vm-ip` on an Ubuntu host.
